# 代理状态总览

Egern 桌面小组件：对比两个策略组的出口，并显示本机网络与直连出口。支持小号、中号和锁屏尺寸。

配色使用系统风格的浅色 / 深色自适应配色，不使用渐变，跟随 iOS 外观自动切换。

## 展示内容

**中号**：左 1/3 是本机，右 2/3 是两个策略组。

| 区域 | 内容 |
| --- | --- |
| 本机 | 网络类型（Wi-Fi 名称，或蜂窝运营商与 4G / 5G）、直连公网 IP 与地区和运营商、直连延迟、内网 IP、IPv6 是否可用、更新时间 |
| 每个策略组 | 状态点、名称、延迟、国旗、出口 IP、出口类型标签、城市与运营商、服务可达性 |

**小号**：上下两栏，上半是策略组 1，下半是策略组 2。每栏有名称、延迟、出口 IP、地区与运营商、服务可达数（如 `服务 4/5`）。小号不查询直连出口。

**锁屏**：只显示两个策略组的名称与延迟。

## 各项含义

- **延迟**：向检测地址连续发 3 次 HTTP 请求，取中位数。其中有失败时追加 `丢N`，3 次全部失败显示“超时”。这是含建立连接的 HTTP 耗时，不是 ICMP 延迟。低于 250 ms 为绿色，低于 600 ms 为橙色，更高为红色，有丢包也显示橙色。
- **直连出口**：用 `DIRECT` 策略请求 IP 查询接口得到的公网 IP，直连延迟则请求国内检测地址。
- **出口类型标签**：来自 ip-api.com 的标记。`机房` 表示被标为托管 / 机房 IP，`移动` 表示移动网络，`代理` 表示被标为代理，`非机房` 表示没有以上任何标记。**“非机房”不等于住宅 IP**，查询服务也没有这类信息。只在 ip-api.com 返回结果时显示，回退到其他接口时没有该标签。
- **服务可达性**：每个策略组分别检测，绿色名称表示可以访问，`?` 开头的橙色表示请求失败或超时，红色 `✕` 开头表示明确被拒绝。
  - 只有 `chatgpt`（接口返回 403 或 `unsupported_country`）和 `claude`（接口返回 403）会判定为“被拒绝”。
  - 其余服务（Gemini、YouTube、Netflix、Disney+、GitHub）**只检测能否访问，不能证明地区解锁**，例如 Netflix 绿色只说明页面能打开，不代表能看全部内容。
  - 被拒绝的判定规则我只在可正常访问的地区测过，没有在受限地区验证；如果你发现误判，请告诉我实际现象。
- **状态点**：绿色表示出口查询和延迟检测都成功，橙色表示只有一项成功，红色表示都失败。

## 使用

1. 把 `status.js` 和 `status.yaml` 推送到仓库 `main` 分支。`status.yaml` 里的 `script_url` 指向该分支，用其他分支或仓库时请自行修改。
2. 在 Egern 中导入并启用模块：
   `https://raw.githubusercontent.com/Alencryenfo/ProxyRules/main/Egern/status/status.yaml`
3. 在 `status.yaml` 的 `env` 里填写策略组名称，或在导入模块时通过模块 `env` 覆盖（模块级优先于小组件级）：

   ```yaml
   modules:
     - url: "https://raw.githubusercontent.com/Alencryenfo/ProxyRules/main/Egern/status/status.yaml"
       env:
         POLICY_1: "你的策略组 1"
         POLICY_2: "你的策略组 2"
         SERVICES_2: "chatgpt,claude,gemini"
   ```

4. 在 iPhone 主屏幕添加 Egern 小组件（小号或中号），编辑并选择「代理状态总览」。

也可以在 Egern 的「工具 → 脚本」中创建本地 generic 脚本，粘贴 `status.js`，在脚本里配置同样的环境变量。

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `POLICY_1` / `POLICY_2` | 策略组名称，需与 Egern 配置中的 `name` 完全一致。留空则该位置显示“未配置” |
| `NAME_1` / `NAME_2` | 卡片上显示的名称，留空则使用策略组名称 |
| `SERVICES_1` / `SERVICES_2` | 要检测的服务，英文逗号分隔，最多 5 项。可选 `chatgpt` `claude` `gemini` `youtube` `netflix` `disney` `github`，默认前五项 |
| `CHECK_URL` | 策略组延迟检测地址，默认 `http://www.gstatic.com/generate_204` |
| `MASK_IP` | 填 `1` 后 IP 只显示前两段（如 `203.0.*.*`），便于截图分享 |

## 说明

- **策略组名称如何传给请求，官方文档没有写明。** 脚本把名称直接作为 `ctx.http` 的 `policy` 参数，直连使用 `DIRECT`，这是参考社区脚本的做法，我没有在真机上验证过。如果两张卡片的出口 IP 和预期不符，先检查策略组名称是否一致。
- 出口信息优先用 ip-api.com（HTTP）和 ipwho.is 同时查询，前者优先；两者都失败时用 api64.ipify.org 取 IP，再由 Egern 的 `ctx.lookupIP` 补全国家和 ASN。ip-api.com 免费版有频率限制，刷新过于频繁可能被限流，此时会自动改用其他接口。
- 访问这些第三方服务会向其暴露对应出口 IP。
- 本机网络类型是根据 Wi-Fi 名称、网络接口名（`en*` 视为 Wi-Fi，`pdp_ip*` 视为蜂窝）和运营商信息推断的，设备 API 没有直接给出连接类型。无法判断时显示“网络未知”。
- 脚本建议 15 分钟后刷新，实际时间由 Egern 和 iOS 决定，可能延迟。每次刷新最多约 25 个请求（延迟 9 个、IP 查询 6 个、服务检测最多 10 个），耗时数秒到十几秒。
- 某一项查询失败时，只影响对应部分，其余信息正常显示。
